# API ตัวคุมสแตกบนบอร์ด (`stack_supervisor`)

ตัวคุมรันบนบอร์ดที่พอร์ต 8091 Backend ส่งต่อคำขอพร้อม header `x-robot-settings-token`
ห้ามให้ Browser ติดต่อบอร์ดตรง ตั้ง token บนบอร์ดด้วย `STACK_SUPERVISOR_TOKEN` ถ้าไม่ตั้ง ทุกคำขอจะได้ 403

## Endpoint

| Method | Path | ใช้ทำอะไร |
|---|---|---|
| GET | `/robot/settings` | ค่าที่ node ใช้จริง ตาม contract ของแท็บ Robot |
| PATCH | `/robot/settings` | ตั้งค่า อ่านกลับ และย้อนกลับเมื่อพัง ตอบเมื่อทำเสร็จ อาจนานราว 1–3 นาที |
| GET | `/robot/preflight` | เหตุผลที่ยังเริ่มไม่ได้ และสถานะการยืนยันตำแหน่ง |
| POST | `/robot/bridge` | `{"action":"arm","confirm":"AREA_CLEAR_REMOTE_IN_HAND"}` หรือ `{"action":"disarm"}` |

Backend แมป `/api/robot/settings` ไปที่ `/robot/settings` และตั้ง timeout ของ PATCH อย่างน้อย 5 นาที

ข้อผิดพลาดตอบเป็น `{"message": "..."}`: 401/403 สิทธิ์, 400/422 ค่าผิด, 409 ยังทำไม่ได้ตอนนี้, 503 ทำแล้วไม่สำเร็จ

ยังเลือกแมพจากเว็บไม่ได้ เพราะ `map` ไม่อยู่ใน contract

## ปุ่มยืนยันตำแหน่ง

`GET /robot/preflight` คืน `localization.state` และข้อความแนะนำ

| state | แสดงบนเว็บ |
|---|---|
| `not_set` | ให้ตั้งตำแหน่ง |
| `searching` | กำลังหาตำแหน่ง ให้ใช้รีโมทขยับช้า ๆ |
| `ready` | พร้อม ให้เทียบตำแหน่งบนแมพกับหุ่นจริง แล้วกดยืนยัน |
| `failed` | ยังไม่สำเร็จ ให้หยุดตรวจ Scan, Map และ TF |

`ready` ไม่ได้พิสูจน์ว่าตำแหน่งถูก ผู้ใช้ต้องเทียบกับหุ่นจริงเอง

## ลำดับเมื่อกด Start

1. แสดงกล่องยืนยันว่าพื้นที่ว่างและถือรีโมทแล้ว ต้องกดทุกครั้ง
2. เรียก `GET /robot/preflight` ถ้า `ok` เป็น false ให้แสดง `problems` และหยุด
3. เรียก `POST /robot/bridge` ด้วย `arm` **ตอนนี้หุ่นจะลุกยืนและจอยถูกปิด**
4. สำเร็จแล้วค่อยส่งมิชชันผ่าน `/missions/start`
5. ใช้ `runId` ใหม่ทุกครั้ง และห้าม publish แบบ retained เพราะบอร์ดจะไม่รับ

บอร์ดปิด bridge เองเมื่อมิชชันจบ 3 วินาที เมื่อไม่มีมิชชัน 60 วินาที และทันทีเมื่อ FAST-LIO เร็วเกิน 1 ม./วิ
เมื่อถูกปิด `rearmRequired` จะเป็น true

## ยังไม่ได้พิสูจน์

- ทดสอบกับ replay และ bridge จำลองเท่านั้น ยังไม่ได้ทดสอบกับหุ่นจริง
- ยังไม่รู้ว่ารีโมทหยุดหุ่นได้ไหมขณะ bridge ทำงาน
