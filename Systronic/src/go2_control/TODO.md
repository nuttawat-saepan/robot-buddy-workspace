# งานที่ค้างอยู่ เรียงตามลำดับที่ควรทำ

รวบรวม 2026-09-10 หลังลงหน้างานวันที่ 7 และวิเคราะห์ bag ที่บริษัท
บางข้อมีคำตอบบางส่วนอยู่แล้วจากการวัด เขียนกำกับไว้ในแต่ละข้อ

```text
5  แบตน้อย                       ต้องเขียนของใหม่
6  segfault กับทาง sdk            งานค้นคว้า ไม่เร่ง เพราะ raw ใช้ได้แล้ว
7  /scan_low                     รอผลเทสก่อน ดูเหตุผลข้างล่าง
```

## 1. `onsite_stack.launch.py`

รวมทุกอย่างไว้ใน launch เดียว **ยกเว้น `unitree_udp_bridge`**

```text
รวมเข้ามา    livox_robot, livox_ground, occupancy_grid_points,
            cmd_vel_udp_relay, mqtt_mission_bridge
อยู่นอก      unitree_udp_bridge     ← โดยเจตนา
RViz        ยังรันที่ ground station แยกเหมือนเดิม
```

`unitree_udp_bridge` ต้องอยู่นอกเพราะเป็นโปรเซสเดียวที่ทำให้หุ่นเคลื่อนที่ได้
และควรต้องพิมพ์คำสั่งที่มีวลีปลดล็อกอยู่ในนั้นทุกครั้ง ไม่ควรติดมากับการสตาร์ต
ทุกอย่างพร้อมกัน

**เหตุผลที่ควรทำก่อนข้ออื่น** ไม่ใช่แค่ความสะดวก — `controller_server` ของ Nav2
activate ไม่ผ่านถ้าเซนเซอร์ยังไม่ส่ง TF ซึ่งเกิดซ้ำหลายรอบวันที่ 7 launch file
จัดลำดับและรอให้ได้ ส่วนหกเทอร์มินัลอาศัยให้คนจำเอง และบอร์ดยัง source
`go2_control` ตัวเก่าจาก `~/UnitreeRos` ทุกเชลล์ใหม่ ซึ่ง launch file ตัดปัญหานี้ออก

## 2. Dev testing panel บนเว็บ

ปรับค่าสดผ่าน `ros2 param set` ทาง `mqtt_mission_bridge` ไม่ต้องรีสตาร์ทอะไร
รายการค่าและผลของการเพิ่ม/ลดแต่ละตัวอยู่ใน `TUNING_AND_TESTPLAN.md` หัวข้อ 4

```text

xy_goal_tolerance, yaw_goal_tolerance
inflation_radius, cost_scaling_factor
โหมด  idle / manual / mission / slow
ปุ่ม  stop / pause / resume     ← ทำงานอยู่แล้ว
```

**ข้อควรระวัง** `xy_goal_tolerance` มีค่าต่ำสุดที่ลดกว่านั้นไม่ได้ — ถูกกำหนด
ด้วยค่าคลาดของ localisation 0.258 ม. ไม่ใช่ความชอบ panel ควรกันไม่ให้ตั้งต่ำกว่านั้น
หรืออย่างน้อยเตือน

และ `--max-linear` / `--max-angular` ของ bridge **ไม่ใช่ ROS parameter**
ปรับสดไม่ได้ ต้องรีสตาร์ท และการตัดของมันชนะ Nav2 เสมอ panel ควรแสดงค่านี้
ให้เห็นด้วย ไม่งั้นจะตั้ง Nav2 ไว้ 0.40 แล้วงงว่าทำไมหุ่นวิ่ง 0.25

## 6. `segfault` คืออะไร และจะกลับไปใช้ `sdk` ได้ไหม

### เกิดอะไรขึ้น

การสร้าง ROS node ใด ๆ บน `ROS_DOMAIN_ID 0` ขณะที่กราฟของหุ่นอยู่ในสายเดียวกัน
จะทำให้โปรเซสตายทันที วัดแล้วทั้งบน MiniPC และบนบอร์ด และเกิดทั้งใน rclpy
และ rclcpp

```text
rclpy.create_node()                       segfault
go2w_cmd_vel_control (C++/rclcpp)         segfault
ros2 topic echo / info / hz บน domain 0   segfault
mission_capture บน domain 0               segfault
```

เป็นที่ชั้น middleware ไม่ใช่ที่ภาษา — `rmw_cyclonedds_cpp` ของ Foxy
(CycloneDDS 0.7) ทนประกาศ participant ของ Unitree ไม่ได้ อาการคู่ขนานคือ
Fast DDS บน domain เดียวกันพ่น `std::bad_alloc` รัว ๆ แทนที่จะตาย

**สิ่งที่ยังไม่รู้** คือ Unitree ส่งอะไรที่ทำให้มันพัง — ยังไม่ได้จับ packet ดู
และยังไม่ได้ลอง CycloneDDS รุ่นใหม่กว่า ซึ่งเป็นสองทางที่จะพิสูจน์ได้

### ทำไม `raw` ถึงรอด

`--mode raw` ไม่สร้าง ROS node เลย มันใช้ CycloneDDS ของ SDK โดยตรง
ส่ง `unitree_api/msg/Request` ลง `rt/api/sport/request` จึงไม่แตะ `rmw`
ที่เป็นตัวพัง

### แล้ว `sdk` ล่ะ

`--mode sdk` ก็ไม่ผ่าน rmw เหมือนกัน ปัญหาคนละเรื่อง — มันเรียก service ชื่อ
`sport` ผ่าน `SportClient` ซึ่งบนหุ่นตัวนี้**ตอบเวอร์ชันได้แต่ไม่ขับล้อ**
วัดแล้วหน้างาน: `rx 10/s`, `move 13/s`, `held 0.05` ต่อเนื่องสี่วินาที
ไม่มี timeout เลย แต่หุ่นไม่ขยับ

เพราะฉะนั้น **การแก้ segfault ไม่ได้ทำให้ `sdk` ใช้ได้** มันเป็นคนละปัญหา
ถ้าแก้ segfault ได้ สิ่งที่จะได้กลับมาคือ `--mode api` และการใช้ `ros2 topic`
ส่องหุ่นได้ ซึ่งมีค่าตอน debug แต่ไม่ได้เปลี่ยนว่าหุ่นเดินได้หรือไม่

**ข้อสรุป** ไม่เร่ง `raw` ทำงานได้และพิสูจน์แล้วว่าหุ่นเดินตาม waypoint ได้จริง
ควรทำเมื่อว่างเพื่อให้ debug ง่ายขึ้น ไม่ใช่เพื่อให้หุ่นเดิน

## 7. `/scan_low` — รอผลเทสก่อน

แนวคิดเดิมคือทำ `pointcloud_to_laserscan` ตัวที่สองที่ `min_height: 0.05`
ส่งเป็น `/scan_low` ให้ local costmap อย่างเดียว ไม่ให้ AMCL

**วัดแล้วเมื่อ 2026-09-10 และผลไม่สนับสนุน** รายละเอียดอยู่ใน
`TUNING_AND_TESTPLAN.md` หัวข้อ 11

```text
เซลล์ที่มีสิ่งกีดขวาง   ทั้งสองความสูง 25993   เฉพาะ 0.25  1299   เฉพาะ 0.05  1101
```

0.05 ไม่ได้เห็นของเพิ่ม มันเห็นของเดิมใกล้กว่าเล็กน้อยเพราะลำแสงเฉียดพื้นก่อนถึง
กำแพง และเสียของที่ 0.25 เห็นไปพอ ๆ กัน ส่วนของที่เห็นเพิ่มในระยะใกล้กระจุกอยู่
ที่มุม 310° ในเฟรมหุ่นตลอดทั้ง bag — เป็นสิ่งที่เคลื่อนที่ไปกับหุ่น

**ถ้าทำตอนนี้จะได้สิ่งกีดขวางผีถาวรที่มุมเดิมใน costmap**

แต่ยังสรุปไม่ได้ว่าไม่ควรทำ เพราะ **ทั้งสอง bag ไม่มีของเตี้ยจริงวางอยู่เลย**
ต้องเทสก่อน

```text
วางกล่องสูงราว 15 ซม. ห่างหุ่นสองเมตร
อัด 30 วินาที
รันเทียบสองความสูงแบบเดียวกับหัวข้อ 11
```

ถ้ากล่องโผล่ที่ 0.05 และไม่โผล่ที่ 0.25 ค่อยทำ `/scan_low` และตอนนั้นต้องแก้
`range_min` ด้วยเพื่อกันวัตถุที่ติดกับหุ่น

## 8. จูนเลี้ยวเพิ่ม

ตอนนี้ `max_vel_theta 0.35` มาจากการลองหน้างาน — 0.6 เลยแล้วแกว่ง 0.2 แทบไม่หมุน

สิ่งที่ทำได้จริงมีจำกัด เพราะสาเหตุไม่ได้อยู่ที่ controller — สแกนที่ฉายมามีลำแสง
ราว 54% และคนละชุดทุกเฟรม หมุนเร็วทำให้กำแพงที่เห็นเปลี่ยนเร็วกว่าที่ AMCL
จะลู่เข้าใหม่ทัน

```text
alpha1 0.03 / alpha2 0.10    ลดไปแล้ววันที่ 7 แต่ ยังไม่ได้วัด
AprilTag                     ทางแก้จริงถ้าลด alpha แล้วยังไม่พอ
```

**ควรวัด alpha ก่อนทำอย่างอื่น** มี bag พอแล้ว ไม่ต้องมีหุ่น เทียบค่าเก่ากับค่าใหม่
อย่างละสองรอบตามที่ `LIVOX_AMCL_TUNING_2026-09-03.md` กำหนดไว้ ถ้าไม่วัด
เราจะไม่รู้ว่าที่แก้ไปช่วยหรือไม่ และโปรเจกต์นี้เคยเจอผลกลับด้านระหว่างรอบแรก
กับรอบสองมาแล้ว

# งานฝั่งเว็บ

ฝั่งหุ่นส่งข้อมูลครบแล้วทุกอย่างที่ลิสต์นี้ต้องใช้ ไม่ต้องรออะไรจากเรา
รูปแบบข้อความอยู่ใน `TUNING_AND_TESTPLAN.md` หัวข้อ 6 และใน docstring ของ
`mqtt_mission_bridge.py`

## 0. แก้ก่อนอย่างอื่น

```text
VITE_MQTT_URL = ws://<ip broker>:9001
```

ตอนนี้ชี้ `192.168.68.63` ซึ่งเป็นซับเน็ตเก่าและคนละเครื่อง **IP นี้เปลี่ยนทุกครั้ง
ที่ Wi-Fi เปลี่ยน** ควรทำให้ตั้งได้จากหน้าจอหรืออ่านจาก backend แทนที่จะ build ติดไป
ไม่งั้นทุกครั้งที่ย้ายไซต์ต้อง build ใหม่

หุ่นต่อ broker ที่พอร์ต 1883 (TCP) ส่วนเบราว์เซอร์ต้องใช้ 9001 (websocket)
คนละพอร์ตแต่ broker เดียวกัน

## 1. วาดแมพ

subscribe `/missions/map` ได้ทุก 30 วินาที ส่งซ้ำเพื่อให้หน้าที่เพิ่งเปิดได้ด้วย

```json
{"width":284, "height":304, "resolution":0.05,
 "origin":{"x":-6.95,"y":-12.2,"yaw":0}, "image":"<PNG base64>"}
```

`resolution` กับ `origin` ไม่ใช่ของแถม — เป็นตัวที่แปลงพิกัดหุ่นเป็นพิกเซล
ถ้าไม่ใช้ marker จะไปวางมั่ว

## 2. วาง marker หุ่น

subscribe `/missions/pose` ทุกวินาที

```json
{"x":2.41, "y":-1.08, "yaw":1.57, "frame":"map", "timestamp":1757230000}
```

```text
px = (x - origin.x) / resolution
py = height - (y - origin.y) / resolution
```

**`height -` ห้ามลืม** แถวแรกของแมพคือด้านล่างในเชิงพิกัดโลก แต่ canvas วาดแถวแรก
ไว้บน ถ้าลืมอาคารจะกลับด้านและไม่รู้ตัวจนเห็นหุ่นเดินทะลุกำแพง

`yaw` เป็นเรเดียน แปลงเป็นองศาแล้วหมุน icon ได้เลย ไม่ต้องคำนวณจาก quaternion
ฝั่งหุ่นแปลงให้แล้ว

ใช้ `timestamp` ตัดสินว่าข้อมูลเก่าไปหรือยัง ถ้าเกินสัก 5 วินาทีควรทำ marker
ให้จางลงหรือขึ้นเตือน — marker ที่ดูสดแต่จริง ๆ ค้างอยู่แย่กว่าไม่มี marker

**ถ้าต้องการวาดกรอบตัวหุ่นด้วย** `base_link` คือจุดกึ่งกลางหุ่นบนพื้น
footprint คือสี่เหลี่ยม 0.70 x 0.50 ม. รอบจุดนั้น หมุนตาม yaw

localisation 0.258 ม. ไม่ใช่ความชอบ ตั้งต่ำกว่านั้นหุ่นจะวนรอบจุดหมายไม่จบ
panel ควรกันไว้หรืออย่างน้อยเตือน

`--max-linear` กับ `--max-angular` ของ bridge **ไม่ใช่ ROS parameter** ปรับสด
ไม่ได้ ต้องรีสตาร์ท และการตัดของมันชนะ Nav2 เสมอ panel ควรแสดงค่านี้ให้เห็น

## 5. โหมด

```text
slow     max_vel_x 0.15, max_vel_theta 0.2 สำหรับที่แคบ
```

`slow` มีประโยชน์ทันทีที่สุด เพราะที่แคบกับที่โล่งต้องการเลขคนละชุด

## 6. แบต

ยังไม่มีทั้งสองฝั่ง `go2w_read` อ่านค่าได้แล้วแต่ไม่มีใคร subscribe และ bridge
ไม่ได้ส่งขึ้น เมื่อฝั่งเราส่งแล้ว หน้าเว็บควรแสดงระดับแบตและเตือนเมื่อต่ำ
