# วัดผลแต่ละเคสเป็นตัวเลขยังไง

เขียน 2026-09-11 คู่กับตาราง 9 เคสในแผนหน้างาน

## ก่อนอื่น มีสาม error ไม่ใช่อันเดียว

สับสนสามอันนี้คือเหตุที่วันทดสอบได้ตัวเลขมาแล้วเอาไปตัดสินใจอะไรไม่ได้

```text
goal error          หยุดตรงไหน เทียบกับที่สั่งให้ไปหยุด  ทั้งคู่ในกรอบ map
                    เป็นเลขของ controller กับ goal checker
                    สคริปต์วัดได้  แต่จะน้อยกว่า xy_goal_tolerance เสมอ
                    โดยธรรมชาติ ต้องดูการกระจายของสิบรอบ ไม่ใช่รอบเดียว

drift correction    AMCL ต้องดึง odometry กลับเข้าแมพเท่าไร คือ map->odom
                    สคริปต์วัดได้ ไม่ต้องใช้ตลับเมตร
                    เป็นเลขที่ตอบว่า AMCL อย่างเดียวพอไหมบนหุ่นตัวนี้

localisation error  หุ่นอยู่ตรงไหนจริง เทียบกับที่หุ่นคิดว่าตัวเองอยู่
                    ** วัดจากในหุ่นไม่ได้เลย **
                    ทุก topic อยู่ใต้ความเชื่อที่กำลังถูกตรวจ
                    หุ่นที่มั่นใจแต่ผิด จะรายงานเลขสวย
                    อันนี้ต้องวัดจากพื้น เทปกาวจุดเริ่ม เทปกาวจุดหยุด วัดระหว่างสองจุด
```

เลขจากสคริปต์ช่วยคัดว่ารอบไหนควรเอาตลับเมตรไปวัด ไม่ได้แทนตลับเมตร

## ตั้งค่าก่อนวันวัด

**อ่าน `map -> base_link` จาก TF ไม่ใช่จาก `/amcl_pose`** AMCL ส่ง pose เฉพาะตอน
อัปเดต ซึ่งเกิดทุก `update_min_d` เมตร ตอนนี้ตั้ง 0.20 แปลว่าหุ่นที่หยุดแล้วถือ pose
เก่าได้ถึง 20 ซม. ซึ่งใหญ่พอ ๆ กับ error ที่จะวัด TF เป็น interpolate ต่อเนื่อง
`testcase_recorder` อ่านจาก TF ให้แล้ว

**รอบที่จะวัด ให้ลด `update_min_d` กับ `update_min_a` เหลือ 0.05** ใน
`config/amcl_livox.yaml` **ก่อน launch** ปรับสดไม่ได้ — Foxy อ่านค่าครั้งเดียวตอน
`on_configure` สั่งทีหลังตอบ success แต่ไม่มีผล เสร็จแล้วค่อยตั้งกลับ

```yaml
update_min_d: 0.05      # จาก 0.20 เฉพาะรอบวัด
update_min_a: 0.05      # จาก 0.10
```

CPU เพิ่มขึ้นเพราะ resample ถี่ขึ้น บอร์ด 8 คอร์ใช้อยู่ 1.59 มีที่เหลือพอ
แต่ดู `measure_board_load.sh` ระหว่างรอบแรกด้วย

## วิธีรัน

```bash
ros2 run go2_control testcase_recorder --ros-args -p case:=01_straight \
    -p goal_x:=4.0 -p goal_y:=0.0
```

Ctrl-C จบรอบ ได้ bag, `samples.csv` 10 Hz และ `summary.json` ใน
`~/go2_testruns/<เวลา>_<ชื่อเคส>/` แล้วพิมพ์สรุปออกหน้าจอ

ถ้าส่ง goal จาก RViz ไม่ต้องใส่ `goal_x/goal_y` โหนดฟัง `/goal_pose` เอง

`summary.json` มีช่อง `ground_truth_error_m` ว่างไว้ให้กรอกเลขจากตลับเมตร
เว้นไว้ตั้งใจ

## แต่ละเคส ดูเลขตัวไหน

```text
1  ไปจุดตรง ๆ            goal_error_m
                        max_dist_after_arrival_m  ใหญ่กว่า goal_error = เลยแล้วถอย
                        recovery_log_lines        ต้องเป็น 0 ไม่งั้นไม่นับว่าผ่าน
                        + ตลับเมตร

2  หมุน 360°             rotated_deg        ควรใกล้ 360
                        closing_yaw_deg    yaw ที่เพี้ยนหลังหมุนครบ  ← ตัวหลัก
                        closing_error_m    ตำแหน่งไม่ควรขยับ ขยับ = scan match หลุด
                        correction_max_jump_m
                        + เทปกาวทำ marker ทิศ วัดองศาจริงเทียบ closing_yaw_deg

3  สี่เหลี่ยม กลับจุดเริ่ม   closing_error_m    ← ตัวหลัก
                        path_map_m เทียบ path_odom_m
                          ต่างกันมาก = AMCL กับ FAST-LIO ไม่ตรงกัน
                        correction_mean_m / correction_max_m
                        + ตลับเมตรจากเทปกาวจุดเริ่ม

4  loop หลายรอบ          รันเคส 3 ซ้ำ 5-10 รอบ แยก case เป็น 04_loop_r1 r2 r3
                        เอา closing_error_m ของทุกรอบมาเรียง
                        คำถามคือความชัน ไม่ใช่ค่าใดค่าหนึ่ง
                        ชันขึ้น = สะสมจริง  แกว่งรอบค่าเดิม = ไม่สะสม
                        ต้องมีอย่างน้อย 5 จุดถึงจะบอกความชันได้

5  อ้อมเสา               min_scan_range_m + min_scan_bearing_deg
                          ระยะที่เข้าใกล้เสาที่สุด เทียบ inflation_radius 0.35
                        path_map_m เทียบระยะเส้นตรง = อ้อมเกินไปไหม
                        max_cmd_angular ส่ายไหม

6  obstacle ตั้งแต่เริ่ม   arrived            ถึงไหม
                        path_map_m         อ้อมจริงหรือทะลุ
                        recovery_log_lines planner คิดออกหรือถอยเอา

7  obstacle กลางทาง      เปิด samples.csv หาจุดที่ min_scan ลดฮวบ
                        แล้วดูว่า x,y ตอนนั้นห่างจากของที่วางเท่าไร = ระยะที่เห็น
                        recovery_log_lines
                        max_cmd_linear ตอนนั้นลดลงไหม

8  obstacle เตี้ย         รันแยก case ต่อความสูง 08_h10 08_h15 08_h20 08_h25 08_h30
                        วางที่ระยะเดิมทุกครั้ง หุ่นยืนนิ่ง อัด 30 วินาที
                        ดู min_scan_range_m ของแต่ละความสูง
                        ความสูงแรกที่ min_scan_range_m ตรงกับระยะที่วาง = ขอบ blind spot
                        ความสูงที่ต่ำกว่านั้นจะรายงานระยะของกำแพงข้างหลังแทน
                        ← เคสนี้ตอบว่าควรทำ /scan_low ไหม อัดให้ดี

9  อุ้มย้าย 1-2 ม.        เริ่มอัดก่อนอุ้ม
                        ใน samples.csv ดู correction กระโดดตอนไหน
                          เวลาจากวางลงจนถึง correction นิ่ง = เวลา recover
                        correction_max_jump_m
                        closing_error_m ไม่มีความหมายในเคสนี้ ข้ามไป
                        + ตลับเมตร วัดว่าสุดท้าย AMCL คิดถูกจริงไหม
```

## สองอย่างที่ต้องทำทุกเคส ไม่มีข้อยกเว้น

**หุ่นยืนนิ่ง 5 นาที ก่อนเริ่มเคสอื่นของวันนั้น** เป็นเคส 1 ในแผนหน้างาน ได้ค่า
`correction_mean_m` ตอนไม่ขยับ เป็นเส้นฐาน ถ้าไม่มี จะแยกไม่ออกว่า error ที่จุดหมาย
มาจากการเดิน หรือมีอยู่แล้วตั้งแต่ยังไม่ขยับ

**สองรอบขั้นต่ำต่อเงื่อนไข** โปรเจกต์นี้เคยได้ผลกลับด้านระหว่างรอบแรกกับรอบสอง
มาแล้วหลายครั้ง รอบเดียวไม่นับ
