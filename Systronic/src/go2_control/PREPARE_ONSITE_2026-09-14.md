```bash
# จาก MiniPC
go2deploy

# ตั้งนาฬิกา — บอร์ดไม่มีแบต RTC บูตมาที่ปี 1970 ทุกครั้ง

# วาง onsite.env กลับ แล้วแก้ IP ตาม Wi-Fi วันนั้น
scp scripts/onsite.env.board.example unitree@<ip บอร์ด>:~/go2_ws/scripts/onsite.env
```

`ROBOT_IP`, `GROUND_IP`, `MQTT_BROKER` เปลี่ยนตาม Wi-Fi ส่วน `UNITREE_IF=eth0`,
`ROBOT_NET_IF=wlan0`, `ROS_DOMAIN_ID=43` และมุมยึด 13.0/0.0/0.35 ไม่เปลี่ยน

**Gate** — `ros2 pkg prefix go2_control` ต้องได้ `/home/unitree/go2_ws/...`
ถ้าได้ `UnitreeRos` แปลว่า source ไม่ครบ

### ขั้น 3 · เปิดทางสั่งเดิน · 5 นาที

```bash

ros2 run go2_control unitree_udp_bridge --mode raw --interface eth0 \
```

**อัด bag ทุกเคส** ไม่มีข้อยกเว้น วันที่ 7 ความต่างระหว่าง "มันเดินเพี้ยน" กับ

## ความเสี่ยงของวันนี้

**FAST-LIO ไหล** เจอสองครั้งวันที่ 7 ทั้งที่ CPU เหลือ พิสูจน์แล้วว่าไม่ใช่ข้อมูลเสีย
เพราะ replay ข้อมูลชุดเดิมออกมาปกติ สมมติฐานที่เหลือคือเริ่มตอนหุ่นยังไม่นิ่ง
**วิธีป้องกันคือให้หุ่นยืนนิ่งสนิท 15 วินาทีแรกทุกครั้งที่สตาร์ต** และเช็ค
`tf2_echo odom base_link` ว่าอยู่ในหลักเมตรก่อนไปต่อ ถ้าเห็นหลักพันขึ้นไป
ให้รีสตาร์ททันที อย่าเสียเวลาไล่หาอย่างอื่น

**เว็บกับ broker** IP เปลี่ยนตาม Wi-Fi ทุกครั้ง ต้องแก้ทั้ง `onsite.env`
ฝั่งบอร์ด และ `VITE_MQTT_URL` ฝั่งเว็บ ไม่งั้นหุ่นส่งขึ้น broker หนึ่งและเว็บฟัง
อีก broker หนึ่งโดยไม่มีอะไรผิดพลาดให้เห็น
